# 三項小改動 — 設計文件

日期：2026-08-24
狀態：已核准，待寫實作計畫

## 背景

三個獨立的小需求，一起提出、一起設計：

1. 會內賽「各組等級均分」重複按時，結果完全一樣（演算法是固定規則），使用者想要的「不滿意再按一次」目前沒有用。
2. 賽程頁／計分頁／觀眾頁看組別跟場地時，只能看文字，想要用固定顏色快速辨識同一組/同一場地。
3. 觀眾頁看進行中的比賽，想要能全螢幕放大單一場比賽，方便架在電視/投影幕上。

三者互相獨立，沒有共用邏輯，只是同一批一起提出、一起做。

## 1. 「各組等級均分」加入隨機打散

**現況**：`src/components/admin/section-groups.tsx` 的 `generateMixed()`，把每個等級的球員依 `players` 陣列原本順序（固定，非隨機）round-robin 分配到 `tournament.groupCount` 組。同樣的球員名單，重複呼叫會分出完全相同的組別。

**改法**：分配前，先把每個等級桶內的球員順序隨機打亂（Fisher–Yates shuffle），再照原本的 round-robin 規則分配。等級分佈的均勻性不受影響（規則本身沒變，只是桶內順序隨機），但每次按結果會不一樣。

**範圍**：純前端修改，只動 `generateMixed()` 這個函式。後端 `groups/generate` API 本來就支援重新分組（`applyGrouping` 會先刪除舊分組再建新的），不用改。

## 2. 組別／場地固定顏色標示

**現況**：`section-matches.tsx`、`section-scoring.tsx`、`matches-tab.tsx` 三個畫面顯示組別/配對/場地時，都只有文字標題（`<Badge>` 或純文字），沒有顏色區分。

**改法**：
- 新增 `src/lib/badge-colors.ts`：提供 `colorForIndex(index: number): string`，回傳一組固定色盤（Tailwind 背景/文字色 class 組合，約 8 色，超過色盤數量就循環取模）。組別跟場地各自呼叫這個函式，用各自的 `displayOrder`（或陣列順序）當 index，兩者的配色**互不相關**（同一個 index 在組別跟場地情境下可能對到一樣的顏色，這是預期的，兩套顏色本來就沒有互相對照的需求）。
- 三個畫面現有顯示組別名稱/配對標籤/場地名稱的 `<Badge>`／標題，全部套用這個顏色，取代目前單純文字或 `variant="outline"` 的樣式。
- 會內賽的配對標籤（例如「A組 vs B組」）：拆成兩個各自上色的小色塊（A 組色 + "vs" + B 組色），不是整個標籤用單一顏色。

> **2026-08-24 修訂**：上線後實測，使用者反映「A組 vs D組」這種配對標籤還是希望**整個標籤當一個單位、單一顏色**辨識（用兩組中順序較前面那組的顏色），不是兩個小色塊拼接。已改成 `PairingHeader` 回傳單一個 `GroupBadge`，文字合併成「A 組 vs D 組」。上面「拆成兩個各自上色的小色塊」那句已經是舊行為，不要照它改。

**範圍**：新增一個共用工具檔（純函式，無狀態），加上三個既有畫面的顯示樣式修改。不影響任何資料流或業務邏輯。

## 3. 觀眾頁：進行中比賽全螢幕放大

**現況**：`src/components/viewer/matches-tab.tsx` 的 `MatchList` 顯示每場比賽卡片，沒有放大/全螢幕功能。

**改法**：
- 在每張比賽卡片上，當比賽「進行中」時（沿用現有的 `isPlaying` 判斷邏輯：`!done && (scoreA > 0 || scoreB > 0)`），額外顯示一個「放大」按鈕。
- 點擊後，用瀏覽器原生 Fullscreen API（`element.requestFullscreen()`）把一個新的全螢幕覆蓋層（大字體顯示這場比賽的雙方隊伍/配對名稱＋即時比分）放到全螢幕。
- 全螢幕畫面本身不能操作計分（純顯示，觀眾頁本來就沒有計分權限）。
- 按 Esc（瀏覽器原生行為）或畫面上的關閉鈕，呼叫 `document.exitFullscreen()` 退出，回到原本的比賽列表。因為 Esc 是瀏覽器原生行為、不會經過關閉鈕的 `onClick`，元件要監聽 `fullscreenchange` 事件來同步「目前是否全螢幕」這個狀態，不能只靠關閉鈕的點擊事件判斷。
- 全螢幕中顯示的比分要即時更新（沿用現有 `revision`/socket 機制帶動的重新 fetch，退出前分數持續反映最新狀態）。
- 瀏覽器不支援 Fullscreen API（極少數情況）時，`requestFullscreen()` 呼叫失敗直接忽略即可，不用額外的相容性處理或錯誤訊息——這是漸進增強，不支援就等於沒有這顆按鈕的效果。

**範圍**：`matches-tab.tsx` 新增一個小型全螢幕覆蓋層元件（可能拆成獨立檔案 `src/components/viewer/fullscreen-match.tsx`），加上比賽卡片的觸發按鈕。不影響其他畫面。

## 已知的簡化

- 顏色色盤選固定的一組色（不做使用者自訂），超過色盤數量就循環，不追求每組都拿到獨一無二的顏色（現有色盤數量下，一般賽事的組數/場地數不會超過，循環情況少見）。
- 全螢幕功能只做「單一比賽放大」，不做「整頁全螢幕」或「多場比賽輪播」。
- 隨機打散不影響等級分佈規則，只影響桶內順序——不處理「使用者想要完全手動指定某幾位球員一定要同組」這類更複雜的需求（不在這次範圍內）。

## 測試

- 隨機打散：確認同樣的球員名單多次呼叫，各組的等級分佈組成一致（等級人數不變），但成員不完全相同（機率上）。
- 顏色工具：`colorForIndex` 對同一個 index 永遠回傳同一個顏色，色盤循環時（index 超過色盤長度）正確取模不會 out of range。
- 全螢幕：這是瀏覽器 API 互動，這個專案沒有瀏覽器層級的自動化測試基礎設施，不新增測試，靠人工驗證。
